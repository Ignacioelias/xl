xl makes Claude work on Excel the way an analyst would

Claude Code can already help with Excel models if you know how to use it: it explains how a model is built, pulls insights, edits inputs and builds think-cell-ready tabs. Out of the box, though, the work is tedious. xl fixes that.

Claude on Excel by default

  • It's slow: the file is reloaded for every question.
  • It hardcodes values and does its own arithmetic.
  • It doesn't say which cell a number comes from.
  • It misses errors in the file.
  • It burns tokens finding its way around the workbook.

Claude on Excel with xl

  • Answers in about half the time (median 35 s → 19 s per question).
  • No hardcoded values by default: Claude writes formulas and Excel calculates them.
  • Every number cites its cell, for example Summary!D42.
  • Checks that catch what it used to miss: a full recalculation, 18 model checks and an open test.
  • Slightly lower API spend, about 10% per question.

The root of the problem

Claude Code has no built-in way to read a spreadsheet. When you ask about a workbook, it writes a short Python script using openpyxl (a library that unzips the .xlsx and reads its XML), runs it, reads what it prints, and then the script ends. For the next question it writes a new script, which starts a new Python process that loads the whole file again. On a 50-sheet business plan that takes 13 to 18 seconds, every time.

openpyxl can see formulas as text, and it can see the values Excel stored the last time someone saved the file. It cannot calculate. So when a question needs a number that isn't already stored ("what if churn were 5%?"), plain Claude either rebuilds the model's logic in Python, where it can easily get the arithmetic wrong, or trusts stored values that may be out of date.

xl changes two things. The workbook opens once and stays in memory, so each follow-up question is answered in about a second. And any number that matters is calculated by Excel itself, running hidden in the background, so the answer is what Excel would show, with the cell reference attached (for example Summary!D42) so you can check it yourself.

What you can ask it to do

“What is in this model?”

Lists sheets, main tables, named ranges and which sheets feed which. “Where is EBITDA?” finds every cell with that label.

“Where does this number come from?”

Walks back through the formulas that feed a cell, or forward to everything that depends on it. Useful on a model someone else built.

“What if churn were 5% instead of 4%?”

Changes the input, lets Excel recalculate, reports the outputs and restores everything. The original file is only saved if you ask for it.

“Check this model for errors”

Recalculates the whole workbook in Excel, lists every error and stale value, runs 18 model checks and confirms the file opens without a repair prompt. It flags broken formulas, circular references hidden by iterative calculation, plugs and SUMs that miss a row.

“Build the think-cell tab for this bridge”

Lays the feed out the way think-cell reads it (year row, blank spacer, check rows), writes the formulas without recalculating your model, and fills in their values so the chart shows the right numbers as soon as the file opens. Before handing over, it checks that every check row is zero and that Excel opens the file without a repair prompt.

Hidden rows or columns nobody remembers

How it works

YouAsk Claude Code a question about a workbook, in plain English or Spanish.
Claude CodeRecognises the task and calls xl instead of writing one-off scripts.
xl kernelHolds the workbook in memory. Finds, reads and traces in about a second per question.
Excel engineA hidden, separate instance. Recalculates, runs what-ifs, renders ranges and test-opens the file.

After Claude edits a workbook, a quick check runs automatically and the findings go back to Claude before it reports the work as done. Excel runs in a private hidden instance, so your own Excel windows are never touched. Originals are never saved over by default: edits and what-ifs happen on working copies, and Claude only changes the original if you tell it to.

xl is a standalone command-line program with its own persistent kernel, so it keeps working if a given chat tool is unavailable. Every command runs the same way when typed by hand in a plain terminal, although using it that way takes some Python. Claude Code is one way to drive it: a lightweight skill teaches Claude when to reach for xl, and a hook runs a quick check after every edit. It is an independent open-source project, not an official Anthropic product.

How to install

Windows laptop with Excel and Claude Code · about 5 minutes

  1. Check you have what it needs Windows 10 or 11, desktop Excel and Claude Code. The installer adds Python 3.14 if it is missing.
  2. Open Claude Code and paste this prompt Any folder will do. The same prompt, the manual steps and everything the installer changes are in INSTALL.md.
    Install xl on this machine and confirm it works. 1. Clone https://github.com/Ignacioelias/xl into %USERPROFILE%\tools\xl. If that folder already holds a clone of this repository, run git pull there instead. If it exists and is not a clone, stop and ask me. 2. Run: powershell -ExecutionPolicy Bypass -File "%USERPROFILE%\tools\xl\install.ps1" -NoPause 3. It must end with six PASS lines and "All checks passed." On any FAIL, show me the exact output and stop. 4. Run `xl help` (fallback: py -3.14 "%USERPROFILE%\tools\xl\xlcli.py" help) and confirm it prints the command list. 5. Tell me in three lines that xl is installed and what I can ask you now. Do not change anything else on my machine.
  3. Claude runs the installer for you It installs Python 3.14 if missing, copies the tool, registers the two Claude Code skills (xl and think-cell feeds) and the hook, and runs six checks with Excel. You want to see this in Claude's output:
    [7/7] Checks PASS Python packages (openpyxl, pywin32, pillow) PASS Excel reachable through COM PASS xl kernel starts and answers PASS Lint fixture: every rule fires on its planted defect PASS Excel opens the fixture without a repair prompt PASS Think-cell feeds: injected values read by Excel, no repair All checks passed.
  4. Use it Start Claude Code in a folder with a workbook and ask: “What is in this model, and does it have any errors?” Claude picks up xl on its own, so there is no command to learn. A typical exchange looks like this:
    > what is in this model and does it have errors? Reading Summary, Inputs, Engine (50 sheets)... Checks: 14 broken named ranges Recalculated in Excel: 3 #REF! cells Summary!D42 EBITDA 2028 = 12.4m ...

xl itself makes no network calls: your workbooks stay on your laptop, and Claude reads what xl prints through Claude Code as usual.
